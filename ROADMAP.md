# Forge Diorama: Roadmap

Read this file at the start of every session. Work only on the phase marked **NEXT**. Before ending a session, update the phase status and add one line to the Session log.

## What this is

A personal portfolio site: an explorable isometric 3D diorama of a forge/workshop on a floating island with three terrain tiers. The forge mixes traditional smithing with art and the rest of what I love: furnace, paint vats, easels, books, maps and a globe, an architecture drafting desk, gaming. Each station will eventually open a piece of my work.

Concept reference: `reference/forge-concept.jpg`. Use it for layout and mood only.

This site is separate from junesforge.com, which is becoming the agency site. It's built to stay and grows by adding stations, not by being redesigned.

## Standing decisions

- **Stack:** SvelteKit (TypeScript, adapter-static) with vanilla three.js. Ask before adding any other runtime dependency.
- **Models:** Kenney assets only (CC0). No other asset sources. Some stations may later be swapped for models made in my own tool, Propsize (it exports three.js JSON and GLB).
- **Art direction comes from rendering, not modelling:** a unified palette, toon shading, outlines, light post-processing, and small effects (fire, smoke, water). Don't chase model detail.
- **Keep it light:** commit only the models actually used, and instance repeated pieces (foliage, rocks). Flag it if the shipped model payload passes ~7 MB (raised from 5 MB on 2026-10-23; about 5.2 MB now).
- **Config-driven:** tier shapes, station slots and the palette live in one config file (`src/lib/scene/config.ts`). All randomness goes through the seeded RNG.
- **Raw Kenney packs** stay in the shared library at `~/Documents/code/3DResources/kenney-models/`, outside this repo. Only models in use are copied into `static/models/kenney/<pack>/`, with the textures they reference and the pack's `License.txt`. Credit every pack used in `CREDITS.md`.
- **World scale:** a person is 2.8 world units tall (`personHeight` in config). Each pack is scaled by its own character height (`packs` in config).
- **Picking models:** I review the index and Claude's suggestions, then approve or give my own shortlist. Claude doesn't pick final models on its own.
- If a phase needs to break a standing decision, stop and ask.

Pieces that should keep their own size next to each other (furnace and anvil, grindstone) stay separate decor, not composites. - **How it works:** a composite is a decor kind with `parts` instead of `file` (`decorKinds` in config). Part offsets are in the kind's own pack units (its kit grid). A part is a model file (any pack) or another kind, so composites nest: a few small composites (a wall with a window, a roof) build many house variants. Each part is drawn instanced, so repeats stay cheap. Station props can use a kind too (`{ kind: 'crypt' }`). The panel thumbnail shows the first part; hover lists every part.
